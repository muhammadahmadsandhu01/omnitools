## 1. Research Methodology & Evidence Scope (Mandatory Clarification)

To maintain absolute fidelity and avoid conflating basic HTTP availability with interactive testing, all 38 surveyed resources are categorized across five explicit verification tiers:

1. **Interactive Browser Testing:** Hands-on browser interaction where inputs were typed, calculation reactivity was evaluated, edge cases were probed, and amortization outputs were verified. Performed on OmniTools and accessible open tools.
2. **Automated HTTP Probe & HTML Inspection:** An automated HTTP request verified HTTP response codes, response payload byte sizes, page titles, H1 headings, form elements, table structures, and script footprints.
3. **Financial Publisher & Lenders Documentation Review:** Inspection of published product documentation, fee disclosure sheets, and calculator explanations provided by national lenders (Chase, U.S. Bank, TD, Barclays, Lloyds, Halifax).
4. **Official Standards / Regulatory Frameworks:** Normative public guidelines and consumer compliance standards published by governmental and quasi-governmental bodies (Consumer Financial Protection Bureau - CFPB, Fannie Mae).
5. **Inaccessible / Blocked Candidates:** Sites blocked by Cloudflare bot management, Akamai edge shields, HTTP 403/405/429 status codes, or connection timeouts. Documented for full transparency without fabricated claims.

## 4. Feature Gap Analysis & OmniTools Implementation Roadmap

### What OmniTools Already Does Exceptionally Well:
1. **Mathematical Rigor:** Closed-form periodic payment formula $M = P \frac{r(1+r)^n}{(1+r)^n - 1}$ with explicit linear fallback ($P / n$) for zero-interest loans, eliminating `NaN` and `Infinity` edge cases.
2. **Dynamic Period-by-Period PMI Cancellation:** Evaluates outstanding balance against the original property price at every single payment period. Automatically drops PMI once the Loan-to-Value (LTV) threshold reaches the target (default 80%).
3. **Dual Payment Frequency:** Full support for both standard monthly payments (12/year) and biweekly payments (26/year), modeling accelerated equity buildup.
4. **Prepayment Flexibility:** Models recurring monthly extra principal payments as well as one-time lump-sum prepayments (either at loan origination or at any specific payment period).
5. **Cash to Close Simulation:** Models upfront purchase closing costs (% of purchase price), discount points (% of loan amount), and flat lender fees, calculating total cash required at closing.
6. **Global Currency Coverage:** Full support for 150+ ISO world currencies with accurate minor unit precision (0 decimals for JPY, 2 for USD/EUR, 3 for BHD/KWD).
7. **Complete In-Browser Privacy:** 100% client-side calculation execution with zero financial payload transmission.

### Concrete Gaps Identified & Justified Remediation:
1. **Missing Reset / Clear Action (Priority 1):**  
   *Gap:* If a user inputs 10+ fields and wants to start over, there is no way to clear the form without refreshing the browser.  
   *Fix:* Implement a prominent `#btn-reset` action button that resets all fields to empty defaults.
2. **Missing Quick Preset Scenarios (Priority 2):**  
   *Gap:* First-time users or those testing hypothetical situations must manually type 8 to 12 fields. Competitors like Redfin and Ramsey offer quick presets.  
   *Fix:* Implement one-click scenario preset buttons ("30-Yr Fixed (20% Down)", "15-Yr Fixed Accelerated", "FHA 30-Yr (3.5% Down + PMI)", "Extra $200/Mo Accelerated", "Zero Down (100% Financed)") that instantly populate realistic inputs while preserving empty initial state on page load.
3. **Monolithic Architecture Extraction (Priority 3):**  
   *Gap:* Mathematical calculations, types, and currency data are embedded inside `MortgageCalculator.tsx` (1,723 lines), making isolated unit testing impossible without mounting React.  
   *Fix:* Extract pure logic to `lib/mortgageEngine.ts`, matching repo architecture (`lib/metaGeneratorEngine.ts`, etc.).
4. **Expanded Educational Content & FAQs (Priority 4):**  
   *Gap:* `MortgageCalculatorSeo.tsx` only had 5 FAQs and lacked detailed worked examples with step-by-step numbers, discount point breakeven formulas, and biweekly comparison mechanics.  
   *Fix:* Expand to 10+ comprehensive FAQs matching Schema.org `FAQPage` schema, worked mathematical examples, and loan comparison guidance.
